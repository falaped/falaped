# Phase 10 — UI Design Contract

> Visual and interaction contract for the Ganhos (earnings ledger) surfaces.
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.

*form/content* semantic. So: **S2 (Novo lançamento) uses `Dialog`**; the three confirmations
(anular / remover procedimento / excluir caso) use `AlertDialog`; **S3 is the one deliberate
exception** — a form living in an `AlertDialog` because the locked decision folds it into the
existing "Encerrar caso" confirmation, which is why S3 carries the extra dismissal contract in (d).

## S1 — Painel de Ganhos: the dual-scope contract

> **This is the single highest comprehension risk on the screen** and the reason this section is
> prescriptive. Locked decision: the three cards are relative to **TODAY**; the chart, the entry
> list and the average follow the **NAVIGATED period**. A doctor looking at March must never read
> the "Mês" card as March's total.

The screen is split into two bands that are visually and verbally separated. The rule the layout
encodes: **everything that changes when you navigate lives inside one framed container whose header
is the navigator. Everything that never changes lives outside it, above.**

```
┌ page: flex flex-col gap-6, p-6, max-w-6xl ───────────────────────────────┐
│ h1 "Ganhos"   +  p "Acompanhe o que você recebeu."   [Novo lançamento]   │
│                                                                          │
│ ── BAND A ── (never changes when navigating) ────────────────────────    │
│ h2 text-sm font-medium text-muted-foreground: "Hoje"                     │
│ grid gap-4 sm:grid-cols-3                                                │
│  ┌ Card ──────────┐ ┌ Card ──────────┐ ┌ Card ──────────┐                │
│  │ HOJE           │ │ ESTA SEMANA    │ │ ESTE MÊS       │  ← text-xs      │
│  │ R$ 1.250,00    │ │ R$ 4.800,00    │ │ R$ 18.300,00   │  ← text-2xl     │
│  │ 21/08/2026     │ │ 18–24/08       │ │ agosto de 2026 │  ← text-xs muted│
│  └────────────────┘ └────────────────┘ └────────────────┘                │
│                                                                          │
│ ── BAND B ── ONE Card; its header IS the period navigator ───────────     │
│ ┌ Card ─────────────────────────────────────────────────────────────┐    │
│ │ CardHeader (border-b): "Período" · [‹][Hoje][›] "agosto de 2026"  │    │
│ │             [☐ mostrar anulados]                                  │    │
│ ├───────────────────────────────────────────────────────────────────┤    │
│ │ grid gap-4 sm:grid-cols-2                                         │    │
│ │  TOTAL DO PERÍODO            MÉDIA POR ATENDIMENTO                │    │
│ │  R$ 18.300,00                R$ 610,00                            │    │
│ │  agosto de 2026              30 atendimentos no período           │    │
│ ├───────────────────────────────────────────────────────────────────┤    │
│ │  daily BarChart (recharts)                                        │    │
│ ├───────────────────────────────────────────────────────────────────┤    │
│ │  Table: Data · Descrição · Forma · Valor · [anular]               │    │
│ └───────────────────────────────────────────────────────────────────┘    │
└──────────────────────────────────────────────────────────────────────────┘
```

**The four mechanisms that make the dual scope legible (all four are required):**

1. **Section headings that name the scope in words.** Band A is headed `Hoje`. Band B's card header
   is headed `Período`. Uses the exact repo pattern `<h2 className="text-sm font-medium text-muted-foreground">`
   (precedent: "Números da conta", `dashboard-home-content.tsx:247`).
2. **Every card carries a concrete-value sub-line** in `mt-1 text-xs text-muted-foreground`
   (precedent: "N encerrados", `dashboard-home-content.tsx:273`). Band A cards print the literal
   date/range they cover (`21/08/2026`, `18–24/08`, `agosto de 2026`). Band B's total card prints
   the navigated period label. A card that states its own range cannot be misread.
3. **Structural containment.** Band B — nav, total, average, chart, table — is a **single `Card`**
   with the navigator in its `CardHeader`. Band A's cards are bare, outside that frame. The frame is
   the boundary between "moves" and "doesn't move".
4. **A drift badge.** When the navigated period is **not** the current month, Band A gets
   `<Badge variant="secondary">Sempre o mês atual</Badge>` next to its `Hoje` heading, and Band B's
   header shows the period label in `font-medium text-foreground` (not muted). When they coincide,
   no badge — no noise on the default view.

**Card labels are locked** (Band A uses the today words, Band B uses the period words — the two
vocabularies never overlap):

| Band | Card label (`text-xs uppercase tracking-wide text-muted-foreground`) | Sub-line |
|------|---------------------------------------------------------------------|----------|
| A | `Hoje` | `21/08/2026` (the literal date, `dd/MM/yyyy`) |
| A | `Esta semana` | `18–24/08` (Mon–Sun, `d–d/MM`) |
| A | `Este mês` | `agosto de 2026` (lowercase month, `capitalize` off) |
| B | `Total do período` | the navigated period label, e.g. `março de 2026` |
| B | `Média por atendimento` | `{N} atendimentos no período` / `1 atendimento no período` |

### The average's legibility (locked)

The denominator is invisible to the doctor, so it is **printed**, always:

- Value: `formatCentsToBRL(average_cents)` — exactly the SQL scalar, `text-2xl font-semibold tabular-nums`.
- Sub-line: `{attendances} atendimentos no período` (singular `1 atendimento no período`).
- `attendances === 0`: value renders `—` (em dash, not `R$ 0,00`) and the sub-line reads
  **"Nenhum atendimento cobrado no período."** `R$ 0,00` would read as a real average of zero.
- A `Tooltip` on the label reads: **"Total do período dividido pelo número de atendimentos: cada
  caso conta uma vez, mesmo com vários procedimentos. Lançamentos avulsos contam um cada."**
- **The UI never computes this.** No `/` and no `reduce` over money in any component. Both
  `average_cents` and `period_cents` are rendered as they arrive from `get_earnings_summary`.

### Period navigation

`?mes=YYYY-MM` search param, RSC re-render — no client fetch. Markup copied verbatim from
`calendar-editor.tsx:1327-1352`: `[‹ size-7 outline icon]` `[Hoje ghost h-7 px-2 text-xs]`
`[› size-7 outline icon]` then the label in `ml-1 text-sm font-medium`. `aria-label="Anterior"` /
`"Próximo"`. Opens on the current month (D-16) — no `?mes` param on first load.

### "mostrar anulados" filter

`Checkbox` + `Label` ("mostrar anulados", `text-sm`) in the Band B header, right-aligned. Drives
`?anulados=1`. When on, voided rows appear interleaved in date order, styled
`text-muted-foreground line-through` with `<Badge variant="secondary">Anulado</Badge>` in the
description cell and **no** void button. **Voided rows never enter the cards, the average or the
chart** — that filtering lives in SQL, never in a component.

### Daily chart

Copied from `growth-chart.tsx` (the repo's only recharts consumer). `"use client"` is mandatory.

- Wrapper: `rounded-xl border border-border bg-card p-4` — but since it lives inside Band B's Card,
  use a plain `div className="px-4 py-4 border-b border-border"` instead of a nested Card
  (one level of depth only, per `ux-ui-minimalist.mdc`).
- `<ResponsiveContainer width="100%" height={240}>` — numeric height, never `aspect`.
- `<BarChart data={byDay} margin={{ top: 8, right: 16, bottom: 8, left: 0 }}>`
- `<CartesianGrid strokeDasharray="3 3" className="stroke-border" />` — token via className, not `stroke`.
- `<XAxis dataKey="day" tick={{ fontSize: 11 }} />` — day-of-month only (`d`), not the full date.
- `<YAxis type="number" tick={{ fontSize: 11 }} width={88} tickFormatter={(v) => formatCentsToBRL(Number(v))} />`
  — **width 88, not 64**: `R$ 1.200,00` does not fit in 64px. See "no abbreviation" below.
- `<Tooltip formatter={(v) => formatCentsToBRL(Number(v))} labelFormatter={(l) => \`Dia ${l}\`} />`
- `<Bar dataKey="cents" fill="var(--primary)" isAnimationActive={false} />`
- When `byDay` is empty the chart is **not rendered at all** — the whole of Band B's body is
  replaced by the empty state. An axis with no bars reads as broken.

`Table` from `components/ui/table.tsx`, cells `px-4 py-3`.

## Currency contract (the one genuinely new pattern)

The repo has **zero** monetary input and **zero** `R$` formatting today. Both halves below are
decided here and apply to **every** amount field in the phase (consultation value, each procedure
line, the avulso amount, and the catalog price in Perfil).

### Input — masked? no. `type="number"`? no. Plain decimal text — yes.

```tsx
<Field data-invalid={!!errors.amount}>
  <FieldLabel htmlFor="entry-amount">Valor (R$)</FieldLabel>
  <FieldContent>
    <Input
      id="entry-amount"
      type="text"
      inputMode="decimal"
      autoComplete="off"
      placeholder="ex.: 250,00"
      className="tabular-nums"
      {...form.register("amount")}
    />
    <FieldError errors={errors.amount ? [errors.amount] : undefined} />
  </FieldContent>
</Field>
```

| Question | Contract | Why |
|----------|----------|-----|
| Masked (digits fill from the right)? | **No** | No masking library is installed and hand-rolling caret management is the classic 3am bug. Masks also fight paste and screen readers. |
| `type="number" step="0.01"`? | **No** | Already rejected in-repo for decimals (`measurement-form.tsx:229,246,265` uses `text`+`inputMode="decimal"`): comma-vs-dot by locale, scroll wheel silently mutating a money value, inconsistent `valueAsNumber`. |
| Raw cents ("25000" means R$ 250,00)? | **No** | Doctor-hostile. Reais with a comma is what he writes on paper. |
| Chosen | `type="text" inputMode="decimal"` + `tabular-nums` + Zod transform to integer cents | Exact repo precedent, mobile numeric keypad, paste-safe, one tested helper. |
| Mobile keyboard | `inputMode="decimal"` (comma-capable numeric pad). The date field uses `inputMode="numeric"`. |
| Empty field shows | Nothing but the placeholder `ex.: 250,00`. Never `R$ 0,00` and never `0` — a pre-filled zero gets submitted by inertia. |
| Pre-filled field shows | The plain decimal, no prefix: `250,00`. The `R$` lives in the **label** (`Valor (R$)`), never inside the value — a prefix inside the value has to be parsed back out on every keystroke. |
| Paste | Must survive `R$ 1.500,50`, `1.500,50`, `1500.50`, ` 250 `. `parseBrlToCents` strips everything outside `[0-9.,-]` (kills `R$`, spaces, non-breaking spaces) **before** removing thousand dots and swapping the decimal comma. This one extra `.replace()` is the difference between working and not on a real paste. |
| Parse | `parseBrlToCents(value): number \| null` in `lib/money.ts` — the phase's only new money logic. Returns integer cents. **One `lib/money.spec.ts`** covering `"250"`, `"250,00"`, `"1.500,50"`, `"0,01"`, `"150.05"`, `"R$ 1.500,50"`, `"abc"`, `""`, `"-5"`. Mandatory: this is a money path. |

**Error copy (PT-BR, locked):**

| Condition | Message |
|-----------|---------|
| Empty, required | `Informe o valor.` |
| Unparseable | `Valor inválido. Use apenas números, ex.: 250,00.` |
| Zero or negative (an *entry*) | `O valor deve ser maior que zero. Para cortesia, encerre o caso sem lançar.` |
| Negative (a *catalog price*) | `O preço não pode ser negativo.` (zero **is** allowed in the catalog — a free procedure is catalogable) |
| Date empty / invalid | `Informe a data no formato dd/mm/aaaa.` |
| Payment method unset | `Selecione a forma de pagamento.` |
| Avulso description empty | `Descreva o lançamento.` |
| Action failed (server) | The result-union `error` string, surfaced via `toast.error(getFriendlyToastMessage(...))`. Never `String(e)`. |

### Display — `Intl`, and **no abbreviation anywhere**

```ts
// lib/formatters.ts (APPEND to the existing file — do not create lib/currency.ts)
const BRL = new Intl.NumberFormat("pt-BR", { style: "currency", currency: "BRL" })
/** Formata centavos inteiros como moeda brasileira (15000 -> "R$ 150,00"). */
export function formatCentsToBRL(cents: number): string {
  return BRL.format(cents / 100)
}
```

`formatCentsToBRL` is the **single** money formatter in the phase — cards, average, table cells,
chart Y axis, chart tooltip, dialog summaries, and the destructive warning in S7 all call it.

**No abbreviated form ("R$ 8,4 mil") exists anywhere, including the cards.** Reasons, in order:
1. **SC-3 requires the totals to reconcile to the cent.** An abbreviated card total that does not
   equal the sum of the visible rows is a defect the doctor will find and distrust. Abbreviation and
   reconciliation are mutually exclusive on the same screen.
2. It costs a second formatter plus its own rounding tests, for zero information gained.
3. A pediatric monthly total is ~`R$ 45.320,00` — 13 characters at `text-2xl` inside a
   `sm:grid-cols-3` card. It fits. The chart axis is handled by `width={88}`.

The `/100` inside `formatCentsToBRL` is presentation-only and its result **never** returns to the
database. No other arithmetic on money happens in JavaScript — no `+`, no `/`, no `reduce`.

### Adjusted-amount signal (locked: every amount is editable)

The consultation value pre-fills from `profiles.consultation_price_cents`; each procedure line
pre-fills from its catalog `price_cents`. Both are **editable**, and the snapshot records what was
actually typed.

When a field's parsed value **differs** from the pre-fill, a single line appears beneath it:

```tsx
{isAdjusted && (
  <p className="text-xs text-muted-foreground">
    Ajustado — catálogo: {formatCentsToBRL(catalogPriceCents)}
  </p>
)}
```

- Muted, not destructive and not accent — an adjustment is normal, not a warning.
- Shows the **original** price, so the doctor can see both numbers and undo mentally.
- For the consultation line the prefix reads `Ajustado — perfil: R$ …`.
- Absent when the value matches, absent when the pre-fill was `NULL` (nothing to differ from).
- No icon, no badge, no color. Zero new components.

When `consultation_price_cents` is `NULL`, the field opens empty with the hint
**"Defina o valor da consulta em Perfil para preencher automaticamente."** and a `Link` to
`/dashboard/profile` in the hint.

## S2 — Novo lançamento (avulso)

**Primitive: `Dialog`** (`components/ui/dialog.tsx`), not `AlertDialog` — this is a form with no
confirmation semantics, and it is not folded into anything. Triggered only by the "Novo lançamento"
button on the Ganhos page (locked: the avulso exists nowhere else).

- `DialogContent className="sm:max-w-lg"`. Title `Novo lançamento`, description
  `Registre um valor recebido que não veio de um caso.`
- Fields, in tab order: `Descrição` (text, **obrigatória**, D-13) → `Valor (R$)` (currency contract)
  → `Recebido em` (masked `dd/mm/aaaa`, defaults to today in `CLINIC_TIME_ZONE`) →
  `Forma de pagamento` (`Segment` group, no default).
- Footer: `DialogClose` `Button variant="outline"` **`Cancelar`** · `Button` (primary)
  **`Salvar lançamento`** / `Salvando…`.
- **Dismissal: S2 inherits S3's dirty guard.** While the form is dirty, Esc and outside-click are
  blocked so typed money is never silently discarded:

```tsx
<DialogContent
  onEscapeKeyDown={(e) => { if (isDirty) e.preventDefault() }}
```

## S3 — The earnings step inside "Encerrar caso" (the hard one)

**Locked:** the form is a **step inside the existing `AlertDialog`**, not a following `Dialog`.
This inherits RESEARCH Pitfall 8, and the mitigation is specified here in full — the executor must
not have to invent any of it.

### (a) The Popover problem, and the actual fix

The real mechanics, corrected: Radix `AlertDialogContent` **portals to `document.body`**, so it is
not clipped by `PopoverContent className="w-64 p-2"`. The "256px-wide dialog" alert-signal appears
only if someone renders a non-portalled surface. The three risks that *are* real:

1. **Unmount kills the form.** `PopoverContent` unmounts when the popover closes. Any dialog
   rendered *inside* `CaseDetailActions` dies with it — taking typed amounts with it. (Today's
   confirm dialogs survive by accident: the modal overlay stops the popover from ever receiving a
   dismiss, so it stays open, invisible, underneath.)
2. **Two nested focus scopes** fight on close; focus returns into a still-open popover.
3. `Popover`'s outside-interaction handling can close the popover when an inner control is clicked.

**Fix — hoist the dialog out of the popover tree.** `CaseDetailActions` is used from exactly one
place (`case-detail-header-toolbar.tsx:41`, `layout="menu"`), so this is a contained edit.

```
case-detail-header-toolbar.tsx  (the new owner of both pieces of state)
├── const [actionsOpen, setActionsOpen] = useState(false)
├── const [closeFlowOpen, setCloseFlowOpen] = useState(false)
├── <Popover open={actionsOpen} onOpenChange={setActionsOpen}>
│     └── <PopoverContent className="w-64 p-2">
│           └── <CaseDetailActions
│                  onRequestCloseCase={() => { setActionsOpen(false); setCloseFlowOpen(true) }} />
└── <CloseCaseWithEarningsDialog          ← SIBLING of <Popover>, never a descendant
       open={closeFlowOpen} onOpenChange={setCloseFlowOpen} … />
```

- In `CaseDetailActions`, the "Encerrar caso" `AlertDialogTrigger` + `AlertDialogContent` are
  **removed**; the button becomes a plain `Button variant="outline" size="sm"` calling
  `onRequestCloseCase()`. Same icon (`LockIcon`), same label, same classes.
- The **"Reabrir caso" and "Excluir caso" dialogs are left exactly where they are.** They are true
  yes/no confirmations with no form state to lose, and they work today. Touching them is
  unnecessary risk. (S7 changes only the *copy* inside the delete one.)

### (b) Date control — masked text, **not** `<input type="date">`

The brief prefers a native date input to remove a portal level. Neither candidate has a Radix
portal, so that argument is neutral — and the repo settles it:

- **`grep 'type="date"'` across `app/` and `components/` returns nothing.** Zero precedent.
- `lib/brazilian-date-form.ts` (`maskBrazilianDateInput`, `isCompleteBirthDateInputString`,
  `parseBirthDateFormValueToIso`) exists, is unit-tested (`brazilian-date-form.spec.ts`) and is
  already used for exactly this shape of field — "Data da medição" in `measurement-form.tsx:196-220`.
- `react-day-picker` in a `Popover` **is** rejected — that is the extra portal level, and it buys nothing.

**Contract (copied from `measurement-form.tsx`):**

```tsx
<Field data-invalid={!!errors.received_on}>
  <FieldLabel htmlFor="entry-received-on">Recebido em</FieldLabel>
  <FieldContent>
    <Input
      id="entry-received-on" type="text" inputMode="numeric"
```

Default value = **today in `CLINIC_TIME_ZONE`**, formatted `dd/MM/yyyy`, computed in the RSC and
passed down as a prop — never `new Date()` in the client and never `toISOString().slice(0,10)`
(RESEARCH Pitfall 4: after 21:00 BRT that is tomorrow). Editable (D-11).

Four fixed values, four short labels. A `Select` would add a third portal level inside a dialog
inside a popover-owning component, and cost two clicks per entry. The repo already ships the right
control: the `Segment` toggle used for "Tipo de marcação" (`availability-panel.tsx:98-122`).


### (e) The case status state machine is NOT altered

Structurally guaranteed, not merely promised:

- **Two sequential client calls, never one combined action.** `updateCaseStatusAction` is untouched:
  same signature, same revalidate targets, same transitions. `createCaseFinancialEntriesAction` is a
  separate call that happens *after* the case is already closed.
- Therefore the earnings step **cannot block the closing** (the closing already committed before the
  form appeared) and **cannot roll it back** (nothing calls `updateCaseStatusAction(caseId, "active")`
  in this flow — ever).
- A failed, abandoned or empty step 2 leaves a correctly closed case with zero entries — which is
  exactly **cortesia (D-09)**, not an error.
- Per CONTEXT: *"o lançamento é efeito colateral do encerramento, não parte dele."*

### D-09 Cortesia must be obvious and non-punitive

`Button variant="ghost"` labelled **"Sem cobrança"** in step 2's footer, at normal size, with no
warning styling, no icon, no confirmation, no destructive color. It simply closes the dialog and
fires `toast.success("Caso encerrado sem lançamento.")`. The step-2 description already names
cortesia in words. A ghost button next to the primary is the standard "this is a legitimate second
option" affordance — a link-styled or hidden exit would read as punishment.

### D-10 Re-closing does not re-ask

The RSC passes `hasEarnings: boolean` down to the toolbar. When `true`, `CloseCaseWithEarningsDialog`
renders **step 1 only** and closes after `updateCaseStatusAction` succeeds, with
`toast.success("Caso encerrado.")`. Step 2 is never reached; nothing is asked. No extra UI, no
"already billed" banner — silence is the requirement.

RESEARCH states this surface is **not verifiable by typecheck**. The plan **must** end S3 with a
`checkpoint:human-verify` marked **[BLOCKING]** — this survives into the plan as such, it is not

6. "Sem cobrança" leaves the case closed with zero entries.

## Explicit Prohibitions (contract violations the checker/auditor should fail on)

1. Any `#hex` or `rgb()` in a component — tokens only.
2. Green or red used to signify money (income/expense coloring).
3. Any abbreviated currency string ("R$ 8,4 mil", "8.4k") anywhere.
4. Any `/`, `*` or `reduce` over money in a React component (except `formatCentsToBRL`'s internal
   `/100`, and the integer-cents sum in S3's live summary).
5. `voided_at` filtering in a component instead of in SQL.
6. Any "editar valor" affordance on an entry — pencil, inline edit, context menu (D-19).
7. Reintroducing the "Agenda" sidebar group or the `CalendarIcon` import (`4475d4d`).
8. Adding `components/ui/chart.tsx` or any new dependency.
9. `<input type="date">` or a `react-day-picker` `Popover` for "Recebido em" — masked
   `dd/mm/aaaa` text via `maskBrazilianDateInput` only.
10. A Radix `Select` for payment method — `Segment` group only.
11. `toISOString().slice(0,10)` or a bare `new Date()` to derive "today" — `CLINIC_TIME_ZONE` only
    (Pitfall 4).
12. `await action()` without a following `router.refresh()` in any client component (Pitfall 5).
13. A default-selected payment method.
14. `font-bold` (700) or a fourth authored font size.
15. "Rounding" the inherited `gap-1.5`/`py-1.5` (6px) or `size-7` (28px) to the 4px scale — see the
    Spacing Scale exceptions box.
